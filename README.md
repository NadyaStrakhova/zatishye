# «Затишье» — сайт проекта

Готовый статический сайт для бесплатной публикации на GitHub Pages.
Сборка, Node.js, серверная часть и платные сервисы для публикации не нужны.
Все изображения, аудио и видео лежат в папке assets и загружаются с самого сайта.
Внешние сайты открываются только по ссылкам посетителя.

## Что внутри

- Визуальная история на основе предоставленной презентации.
- Плавный переход между тремя сценами при прокрутке.
- Две отдельные кнопки аудио: звуковой ландшафт цунами и эскиз хора.
- Встроенный видеопример в разделе лабанотации.
- Основная научная статья и ещё две статьи со ссылками.
- Семь художественных референсов: четыре из презентации, David Bowen, Ryoji Ikeda и Hakanaï.
- Контакты всех пяти участниц команды; Telegram-ссылки для указанных Telegram-аккаунтов.
- Презентация PDF для скачивания.
- Мобильная версия, увеличение изображений, краткие текстовые версии разделов.
- Управление с клавиатуры, режим уменьшенного движения, отсутствие автозапуска звука.

## Сначала посмотрите локально

1. Распакуйте архив.
2. Откройте папку zatishye-site.
3. Откройте index.html двойным щелчком.
4. Проверьте кнопки «Слушать цунами», «Слушать хор» и видео.

Обычный сайт работает и при локальном открытии. Кнопка «Поделиться сайтом»
начнёт выдавать публичную ссылку после публикации.

## Публикация на GitHub через браузер

### 1. Создайте репозиторий

1. Войдите в свой аккаунт на https://github.com.
2. Нажмите «+» в правом верхнем углу → New repository.
3. Назовите репозиторий, например zatishye.
4. Выберите Public — это нужно для GitHub Pages на бесплатном тарифе.
5. Нажмите Create repository.

Репозиторий будет хранить файлы, а GitHub Pages покажет их как обычный сайт.

### 2. Загрузите содержимое папки сайта

1. В пустом репозитории выберите uploading an existing file.
   Если файлы в репозитории уже есть: Add file → Upload files.
2. Откройте распакованную папку zatishye-site.
3. Перетащите ВЕСЬ ЕЁ СОДЕРЖИМОЕ в окно загрузки:
   index.html, styles.css, script.js, README.md, CREDITS.md и папку assets.
4. Дождитесь завершения загрузки файлов.
5. Нажмите Commit changes.

Важно: загружайте содержимое папки, а не сам ZIP-архив.
В корне репозитория сразу должен быть виден index.html, рядом с ним — assets.
Вариант «затишье/затишье/index.html» добавит лишний уровень папок и не подходит
для описанной ниже настройки.

GitHub разрешает до 100 файлов за одну браузерную загрузку и до 25 MiB на файл.
В этом комплекте меньше 100 файлов, каждый меньше 25 MiB.
Скрытый пустой файл .nojekyll тоже можно загрузить; он отключает обработку Jekyll.
Если он не появился в окне Finder и не был загружен, текущие обычные HTML/CSS/JS
и папка assets всё равно пригодны для стандартной публикации Pages.

### 3. Включите GitHub Pages

В репозитории откройте:

Settings → Pages → Build and deployment.

- Source: Deploy from a branch.
- Branch: main.
- Folder: / (root).
- Save.

Подождите завершения публикации. Её состояние видно во вкладке Actions.
Когда публикация завершится, в Settings → Pages появится ссылка на сайт.

Адрес обычно имеет вид:
https://ВАШ-ЛОГИН.github.io/zatishye/

Подставьте свой логин и настоящее название репозитория.
Это пример адреса, а не уже опубликованный сайт.
Ссылка github.com/ВАШ-ЛОГИН/zatishye ведёт на код; посетителям нужна ссылка
с доменом github.io.

### 4. Проверьте сайт перед QR-кодом

1. Откройте публичный адрес в новой вкладке.
2. Проверьте оба аудиофрагмента.
3. Запустите видео, попробуйте полноэкранный режим.
4. Откройте научные ссылки и Telegram.
5. Проверьте сайт на телефоне, желательно через мобильный интернет.

Если видите 404, проверьте:
- index.html лежит в корне;
- в Pages выбраны main и / (root);
- загрузка и публикация завершились;
- имена папки assets и файлов не были изменены.

## QR-код для сайта

Создавайте QR-код ПОСЛЕ публикации — на реальный адрес github.io.

В Chrome на компьютере:
1. Откройте опубликованный сайт.
2. Меню с тремя точками → «Трансляция, сохранение и отправка»
   (в англоязычной версии Cast, save, and share).
3. «Создать QR-код» → скачать изображение.
4. Используйте QR-код в своих материалах и проверьте его камерой телефона.

Название пункта меню может зависеть от языка браузера.
Официальная инструкция: https://support.google.com/chrome/answer/10051760

QR-код останется рабочим при обновлении содержимого по прежнему адресу.
После распространения QR-кода сохраняйте логин, имя репозитория и публичный путь сайта.

## Как редактировать

- Текст, ссылки, контакты, список статей и референсов: index.html.
- Цвета, отступы, мобильная версия: styles.css.
- Плееры, меню, увеличение изображений, переходы сцен: script.js.
- Картинки презентации: assets/slides.
- Аудио: assets/audio/tsunami.mp3 и assets/audio/choir.mp3.
- Видео: assets/video/labanotation.mp4.
- Превью видео: assets/video/labanotation-poster.jpg.
- Презентация для скачивания: assets/presentation.pdf.
- Основная научная статья: assets/papers/macinnes-2013.pdf.

Оригинальная визуальная вёрстка презентации сохранена как изображения.
Чтобы изменить текст внутри этих изображений, измените исходную презентацию,
экспортируйте соответствующую страницу в картинку и замените её файлы в
assets/slides: полную версию и версию с суффиксом -small.
HTML-пояснения, карточки и ссылки редактируются независимо в index.html.

Все внутренние пути относительные и начинаются с ./assets или ./styles.css.
Сохраняйте их относительными: так сайт будет работать внутри пути репозитория.

Для замены медиа оставляйте текущие имена файлов либо обновите соответствующий
путь в index.html. Используйте MP3 для звука и MP4 с H.264/AAC для видео.
Длинные исходные WAV-файлы в комплект не включены: версии для сайта уже
подготовлены из них.

Изменённые файлы снова загрузите через Add file → Upload files → Commit changes.
GitHub Pages обновит сайт автоматически. При необходимости обновите вкладку
без кэша: Cmd+Shift+R на Mac или Ctrl+Shift+R в Windows.

## Необязательный запуск через локальный сервер

Если хотите проверить сайт через http, откройте Terminal в папке zatishye-site
и выполните команду:

python3 -m http.server 8000

Откройте http://localhost:8000.
Остановить сервер можно сочетанием Ctrl+C.

## Научные подписи

12 минут — разброс между крайними ретроспективными оценками времени прихода.
Это не 12-минутная задержка расчёта или выдачи исторического предупреждения.
Хоровой файл — электронный эскиз, а не запись живого хора.
Звуковой ландшафт — сонификация данных, а не историческая аудиозапись цунами.
Сценическое действие является художественной интерпретацией.
